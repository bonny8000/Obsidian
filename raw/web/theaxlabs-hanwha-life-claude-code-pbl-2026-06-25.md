# Hanwha Life — Business Teams Build Agents Themselves (Claude Code, 6-Week PBL)

**Publisher:** AX LABS (TheAxLabs), case study. Author/date not explicitly stated.
**Capture status:** Fetched via web_fetch 2026-06-25; AI-written summary (not verbatim). Numbers (20 participants, 5 teams, 4 consultants, 6 weeks) and the week-by-week plan are from the case page.

## Summary

Hanwha Life (한화생명) ran a **6-week Project-Based-Learning (PBL)** program with AX LABS in which **20 business experts with no coding background** built working AI agents themselves using **Claude Code**. The thesis: connecting domain expertise to an AI coding environment requires **executing a full project cycle**, not lecture-based training — so the deliverables stay **owned, extendable assets of the business teams**, not external-contractor output.

## Key Points

- **Team composition:** 20 Hanwha Life domain experts (7–10+ yrs experience, no coding background), organized into **5 units of 4**. Support: **4 AX LABS consultants** (1 PM + 3 on-site advisors), on-site daily 8 AM–6 PM.
- **6-week timeline:**
  - **Wk 1 — Definition:** design-thinking workshops, persona mapping, user journeys, workflow docs → agent spec, journey maps, architecture draft.
  - **Wk 2 — Data & Architecture:** identify real data sources, define schema, secure access rights, finalize architecture → data-requirements doc, confirmed architecture, **live data environment**.
  - **Wk 3–4 — Building:** Claude Code implementation of core features, UI, data integration → working prototypes. Mid-wk-4 **cross-unit review** → roadmap revisions.
  - **Wk 5 — Refinement:** integrate feedback, validate on live data, improve UX.
  - **Wk 6 — Presentation:** executive demos, business-led explanations.
- **Method highlights:**
  1. **Boundary-setting before code** — define "what the agent does vs. doesn't," role boundaries, and **Human-in-the-Loop** decision points up front to prevent scope creep.
  2. **Real-data-first** — Wk 2 locks in actual sources/schemas/permissions (not demo data), so outputs reflect real business conditions.
  3. **Direct code ownership** — participants author the code in Claude Code; consultants advise on architecture/data/debugging rather than writing it for them.
  4. **Parallel, non-uniform pacing** — 5 units move on different topics at different speeds; consultants rotate between 2-team coverage and 1:1 support, resolving blockers same-day.
- **Quoted principle (KO):** "무엇을 만들지 정하는 일, 필요한 데이터를 확인하는 일, 구현 가능한 구조로 줄이는 일, 막히는 코드 지점을 넘는 일이 한 흐름 안에 있어야 했습니다" — problem definition, data verification, feasible structuring, and code-unblocking must live in **one continuous flow**.
- **Outcomes:** 20 non-developers delivered near-full-stack agents independently; retained ability to extend/maintain post-program; all 5 units passed executive presentations; participants gained Claude Code competency + domain→code translation skill.
