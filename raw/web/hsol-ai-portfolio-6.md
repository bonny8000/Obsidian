## Summary
This article explores applying Palantir Foundry's "Object Backend" data model to a personal Obsidian vault to create a structured, queryable AI portfolio. The author seeks a middle ground between table-centric tools like Notion and unstructured tools like Obsidian by adopting a rigorous ontology.

## Key Points
- **Ontology Adoption:** Uses Foundry's meta-types (Object Type, Property, Link Type, etc.) to define personal history.
- **ObjectView:** A design philosophy where the UI is a deterministic function of the underlying data graph.
- **Graph Retrospection:** Using structured links to recall career decisions and projects more accurately than memory.
- **Implementation:** Uses folder structures for ontology and wikilinks for relationships within Obsidian.
